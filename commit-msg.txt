ci: flatten packages-* artifact into a single directory

The packages-${{ matrix.os }} artifact zip previously preserved each
project's own src/{Project}/bin/Release/ path (one nupkg/snupkg per
packable project), so downloading it produced a nested folder structure
instead of a flat set of package files.

Add a "Collect packages" step (modeled on SysML2Tools' build.yaml, which
uses `dotnet pack --output ./artifacts/packages` for its single packable
project) that copies every project's *.nupkg/*.snupkg into one flat
artifacts/packages/ folder after packing, and upload from there instead.

Kept `dotnet pack` itself writing to each project'\''s own bin/Release
(rather than adding --output directly to the pack command) because this
repo packs two projects (DemaConsulting.Speech and
DemaConsulting.Speech.Cli) whose nupkg file names both start with
"DemaConsulting.Speech." - collapsing them into one directory before the
existing FileAssert api-docs check would make its glob pattern
(DemaConsulting.Speech.*.nupkg) ambiguously match both packages, and
Microsoft.Extensions.FileSystemGlobbing (which FileAssert uses) has no
bracket/brace/exclude syntax to disambiguate them by name. Keeping pack
per-project preserves the existing, unambiguous FileAssert check path,
and the new copy step only affects the upload.
