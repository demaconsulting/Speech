### EspeakIpaRenderer Verification

#### Verification Approach

`EspeakIpaRenderer` is verified by unit tests in
`test/DemaConsulting.Speech.Phonemes.En.Tests/RenderingSubsystemTests.cs` (the `EspeakIpaRenderer_*` tests) that run the
real phonemizer, which its design documents as the producer of its input, and the renderer. The main evidence is the
golden corpus `TestData/piper-ipa-golden.tsv`: the rendering of every one of the 150 reviewed sentences with the token
ids of the Piper voice's symbol table, regenerated by `regenerate-goldens --renderers` and reviewed. The exhaustive
symbol coverage is the subsystem test.

#### Test Environment

- **Framework**: xUnit v3 running under the .NET SDK
- **Execution**: `dotnet test` invoked by `build.ps1` and the CI pipeline
- **Files**: the golden file and a trimmed copy of the Piper voice's configuration (the symbol table), copied next to
  the test assembly
- **Isolation**: no network, no model

#### Acceptance Criteria

Every sentence of the golden corpus (at least 150) renders to exactly its reviewed string, non-empty, with no symbol
outside the Piper table, and its token ids equal the golden ids; a host IPA override `ɹɪˈkɔɹd` renders unchanged; the
text `Hi 😀 there` renders as `hˈaɪ ðɛɹ` with one string per item and an empty one for the emoji; a null text, a part
limit of 15 and the undefined profile 99 are rejected with argument errors.

#### Test Scenarios

##### Golden corpus

**Test**: `EspeakIpaRenderer_Render_Sentences_RenderTheReviewedPhonemeStrings`

##### IPA override and unsupported token

**Test**: `EspeakIpaRenderer_Render_IpaOverrideAndUnsupportedToken_AreHandledPerItem`

##### Invalid arguments

**Test**: `EspeakIpaRenderer_Render_InvalidArguments_AreRejected`
