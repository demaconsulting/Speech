### KokoroPhonemePipeline Verification

#### Verification Approach

`KokoroPhonemePipeline` is verified by unit tests in
`test/DemaConsulting.Speech.Onnx.Kokoro.Tests/SynthesisSubsystem/KokoroPhonemePipelineTests.cs` that run the whole
text-to-token path for real and need no ONNX model: the model's own English text analysis (the real
`EnglishTextAnalyzer`), the session's own sentence chunking (`SentenceChunker.ChunkAligned`), the real phonemizer and
renderer of Phonemes.En and Kokoro's real vocabulary. The main evidence is the golden corpus
`TestData/kokoro-pipeline-golden.tsv`: 41 sentences written for this repository (12 sentences that each carry both
readings of a heteronym such as `record` or `wind`, 18 general sentences with numbers, dates, currency,
abbreviations and unknown names, and 11 single-reading sentences), with the phoneme string and the token ids that the
engine feeds the model for each chunk. The golden records the text analysis's actual decisions, not an ideal: three
heteronym sentences of the first draft (`read`, `lead` and `content` twice in one sentence) were replaced because the
classifier labels both occurrences alike, which is a known weakness of the analysis and not of the pipeline. For a
heteronym the golden pins the committed model's reading, right or wrong; whether the reading is right is judged by the
Text.En trainer's statistical gate through the regression overlay (see *SpeechTextEn System Verification*). The
habitual *I read every night before bed.* allows both readings, so it was forked into a present sentence (e05, *Nowadays
I read every night before bed.*) and a past sentence (e11, *When I was a child, I read every night before bed.*).

A change in the golden means the audio changes, so a changed line is reviewed by listening as well as by reading. The
pipeline goldens are not regenerated by an in-repository tool: they are updated by hand from the actual output of the
failing test (the tools README says so).

#### Test Environment

- **Framework**: xUnit v3 running under the .NET SDK
- **Execution**: `dotnet test` invoked by `build.ps1` and the CI pipeline
- **Project**: `test/DemaConsulting.Speech.Onnx.Kokoro.Tests`
- **Files**: the golden file, copied next to the test assembly
- **Isolation**: no network, no ONNX model; the pipeline, the phonemizer, the renderer and the vocabulary are
  immutable and shared by the tests of the class

#### Acceptance Criteria

Every one of the 40 golden sentences produces exactly its pinned phoneme string and token ids, one chunk per segment;
in each of the 12 heteronym sentences the token ids differ from the ids of the same text spoken with default
readings; the function words of `A cup of the tea and a bowl of the soup.` come out in their weak forms (the ids of
the renderer with weak forms on, which differ from the full forms); forty copies of a sentence with clause marks are
split into at least three parts of at most 510 ids, each but the last ending in a comma or a period, carrying at
least forty times the ids of the sentence; empty text and an emoji produce no part; and a null text is rejected with
`ArgumentNullException`.

#### Test Scenarios

##### Golden corpus

**Test**: `KokoroPhonemePipeline_GoldenSentence_ProducesPinnedPhonemesAndTokenIds` (a `[Theory]` over the 41 rows)

Each sentence is analyzed and chunked as a session does, and each chunk is phonemized and tokenized; the phoneme
string and the token ids are compared with the pinned ones.

##### Heteronym readings reach the model

**Test**: `KokoroPhonemePipeline_HeteronymSentence_UsesTheChosenReadings` (a `[Theory]` over `s01` to `s12`)

The sentence is spoken with the annotations of the real analysis and with none; the token ids differ.

##### Function words are weak

**Test**: `KokoroPhonemePipeline_FunctionWords_AreSpokenInTheirWeakForms`

The pipeline's ids equal those of the Misaki renderer with weak forms on and differ from the full forms, so the
default of the pipeline is observable.

##### Long text is split without loss

**Test**: `KokoroPhonemePipeline_TextBeyondTokenLimit_IsSplitAtClauseBoundariesWithoutLoss`

Forty sentences give at least three parts, each within the limit, with every sound present and every part but the
last ending at a clause mark.

##### Empty text and invalid arguments

**Test**: `KokoroPhonemePipeline_EmptyOrSoundlessText_ProducesNoPartsAndNullIsRejected`

Empty text and an emoji give an empty list; a null text throws `ArgumentNullException`.
