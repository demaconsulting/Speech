### MainWindowViewModel

**Purpose**: Present the main window's navigation state: the ordered list of capability panels,
the currently selected panel, and the window title.

**Data Model**:

| Member | Type | Purpose |
| --- | --- | --- |
| `Title` | `static string` | Window title naming the four panels |
| `Panels` | `ObservableCollection<DemoPanelViewModel>` | The ordered navigable panels |
| `SelectedPanel` | `DemoPanelViewModel?` | The panel currently shown |
| `DeviceSelection` | `DeviceSelectionViewModel` | The injected device panel state |
| `ModelCatalog` | `ModelCatalogViewModel` | The injected catalog panel state |
| `Synthesis` | `SynthesisPanelViewModel` | The injected text-to-speech panel state |
| `Recognition` | `RecognitionPanelViewModel` | The injected speech-to-text panel state |

**Key Methods**: The constructor is the only behavioral member. It builds `Panels` once, by
wrapping each injected panel view model in a titled `DemoPanelViewModel` in the fixed order Audio
Devices, Model Catalog, Text to Speech, Speech to Text, and then selects the first entry. The shell
never constructs or replaces panel state itself. `SelectedPanel` is generated by
`[ObservableProperty]` and raises change notification only when the assigned value differs from the
current one, so the bound view can swap panels with no code-behind and is not asked to swap on a
no-op assignment.

**Error Handling**: The constructor throws `ArgumentNullException` when any of the four
panel view models is null, because the demo composes manually and the constructor is the only place a
missing collaborator can be detected before a half-composed window reaches a user.

**Dependencies**: `DemoPanelViewModel` and the four panel view models, through their concrete
types only. It never touches the library, the demo's service seams, or Avalonia.

**Callers**: The `App` composition root (which constructs it and assigns it as the main window's
data context) and `MainWindow.axaml` (which binds to it).
